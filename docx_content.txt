Abstract The Duel Arena system is a web-based, real-time, two-player competitive arena game designed to demonstrate foundational distributed computing principles, including server-authoritative state synchronization, client-side snapshot interpolation, deterministic race condition resolution, and event-driven WebSocket communication. In traditional distributed game systems, permitting clients to calculate canonical coordinates or declare item claims introduces significant state divergence, desynchronization anomalies, and cheating vulnerabilities. Duel Arena eliminates these issues by employing a strict Authoritative Client-Server Architecture. Clients capture directional intent via keyboard inputs (WASD and Arrow keys) and dispatch sequence-numbered input packets to the server. The server runs a fixed 30 Hz physics simulation loop, enforces arena boundaries, normalizes velocity vectors, evaluates coin collection collisions atomically, maintains authoritative match timing (120 seconds) and scoring, and broadcasts world state snapshots to connected clients at 20 Hz. Clients reconstruct fluid 60 FPS motion across variable network latencies using a 100 ms snapshot interpolation buffer. The system incorporates robust room lifecycle management (WAITING, COUNTDOWN, PLAYING, FINISHED, RESETTING, ABANDONED) and an isolated, development-only dual-player testing mode protected by server-side production safeguards. The project serves as an educational demonstration of distributed state replication, conflict resolution, and fault-tolerant session handling. 2. Introduction Modern distributed interactive applicationsΓÇösuch as real-time collaborative editors, financial exchanges, and multiplayer gamesΓÇödepend on architectures where multiple remote clients interact concurrently with shared, mutable state. Unlike stateless request-response web services, real-time distributed systems must continuously synchronize continuous state across unreliable networks subject to variable latency, packet jitter, and disconnections. A central engineering challenge is maintaining state consistency without trusting client-side computations. If clients directly broadcast their positions or score increments, malicious actors or network desynchronization can corrupt the global application state.Duel Arena was developed to explore and demonstrate solutions to these challenges in a compact, self-contained TypeScript monorepo. Two players join an isolated match room via unique 6-character room codes. Rather than calculating world physics locally, clients function as input samplers and presentation renderers. The central server owns the canonical world state, integrating physics, resolving simultaneous resource competition deterministically, and broadcasting authoritative state snapshots. The project is an educational artifact intended for college-level Distributed Computing Systems evaluation, illustrating real-time network protocols, concurrency arbitration, and state replication. 3. Theoretical Background 4.1 Distributed Systems and Real-Time State Consistency A distributed system consists of autonomous computing nodes that communicate over a network to coordinate actions. In interactive distributed simulations, the primary challenge is achieving consistent views of rapidly changing state in the presence of non-deterministic network delays (╬ötlatencyΓÇï) and packet arrival variance (jitter). Two primary consistency models exist: Peer-to-Peer (Lockstep / Deterministic Consensus): Every node executes identical simulation code. Inputs are exchanged before advancing each frame. This model suffers severe latency degradation, as the entire simulation stalls to accommodate the slowest node. Client-Server State Replication: A dedicated server advances the simulation independently and broadcasts authoritative state updates. This model isolates client latency, prevents local tampering, and provides a single total ordering of events. 4.2 Authoritative Server vs. Dumb Terminal Model In an authoritative architecture, the client is neither fully autonomous nor a simple streaming terminal: Client-Side Responsibilities: Input capture, local prediction for immediate responsiveness, and interpolation of received world states. Server-Side Responsibilities: Input validation, speed normalization, collision detection, authoritative clock management, and snapshot broadcasting. Clients never send: &quot;My character is at (450,300)(450, 300)(450,300) and I picked up Coin #3.&quot; Clients only send: &quot;At timestamp TTT, my directional input is (+1,0)(+1, 0)(+1,0).&quot; 4.3 Snapshot Interpolation and Jitter Buffering Because WebSocket packet arrival is non-deterministic, rendering entities immediately upon snapshot arrival produces visible stuttering and jitter. Duel Arena implements Snapshot Interpolation (LERP). Without arbitration, both players might receive credit (a double-allocation anomaly).
